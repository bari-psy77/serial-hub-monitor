# 로그 뷰어 (과거 로그 불러오기) 설계

- 날짜: 2026-08-14
- 상태: 사용자 승인됨 (대화에서 설계·결정 사항 합의)
- 근거 요청: "이전에 있던 로그를 불러와서 분석" — 필터드뷰처럼 검색·필터링, 멀티 파일,
  별도 창/메인 창 통합 둘 다.

## 1. 목적

과거 로그 파일을 열어 라이브 세션과 같은 도구(검색·필터·하이라이트·타임스탬프 모드·
결과 저장)로 분석한다. 대상 파일은 Serial Hub 가 기록한 포트별 파일·병합 파일이 기본이고,
형식을 모르는 텍스트 파일도 열화 없이(원문 그대로) 열린다.

## 2. 확정된 결정 사항 (사용자 합의)

| 결정 | 내용 |
|---|---|
| 로드 방식 | **항상 전체 로드.** 큰 파일(합계 200MB 초과)은 로드 전에 경고 확인만 띄운다 |
| 창 형태 | **QDockWidget** — 메인 창 하단에 도킹이 기본, 드래그로 떼어내면 독립 창 (둘 다 지원) |
| 멀티 파일 | 한 뷰어에 여러 파일을 시간순 병합(파일별 체크박스), 뷰어 자체도 여러 개 |
| 진입점 | 파일 메뉴 "로그 파일 열기(뷰어)" (다중 선택) + 뷰어 안의 [파일 추가] |

## 3. 구성요소

### 3.1 core/logfile.py (신규, Qt 비의존)

**파서** — 파일 형식은 **파일 단위**로 정한다: 앞쪽 비어 있지 않은 50줄 중 먼저 매치되는
형식이 그 파일의 형식이고, 형식이 정해진 뒤에도 안 맞는 줄(배너 등)은 그 줄만 plain 으로
받아들인다 (버리지 않는다).

1. 병합 형식: `[HH:MM:SS +  123.4s] [PORT] 본문` → 출처 = PORT (MARK 포함),
   t_wall 은 파일 수정일의 날짜 + 시각으로 복원 (표시는 시각만 쓰므로 날짜 오차 무해)
2. 포트 파일 형식: `[YYYY-MM-DD HH:MM:SS.mmm] 본문` → t_wall 완전 복원, 출처 = 파일명
3. 그 외: plain 열화 — 본문 그대로, t_wall = 파일 수정 시각, 출처 = 파일명

공통: 본문이 `>>> ` 로 시작하면 is_tx. 인코딩은 utf-8 `errors="replace"`.
파일은 읽고 즉시 닫는다(잠그지 않는다). 기록 시 이미 redact 를 거친 파일이므로
뷰어는 재마스킹하지 않는다.

**LogFileStore** — 읽기 전용 스토어. `ConsolePane` 이 실제로 쓰는 최소 인터페이스만
구현한다: `pull_with_gap(after_seq, ports, limit)` / `pull` / `last_seq()` / `counters()`.
- `add_file(path)` 로 파일을 추가하면 전 라인을 t_wall 기준(동률·미상은 파일 내 순서 유지)
  으로 재정렬하고 seq 를 다시 부여한다 — 추가 후 UI 는 `reload()` 로 다시 그린다.
- 소스 키: 병합 파일이면 라인의 포트명, 그 외는 파일명(확장자 제외). 키가 겹치면
  `이름(2)` 식으로 구분한다.
- 실패한 파일은 예외 대신 `(path, 사유)` 목록으로 보고한다 — 빈 화면 금지.

### 3.2 ui/log_viewer.py (신규)

- `LogViewerWidget(QWidget)` — 필터드뷰와 같은 상단 바(필터 입력·Aa·.*·소스 체크박스·
  [파일 추가]·[결과 저장]) + `ConsolePane`(show_prefix=True, state_pill 숨김,
  extra_filter=필터 매치, 프로파일 하이라이트 룰 적용). 소스 체크박스 = LogFileStore 의
  소스 키. 전부 plain 파일이면 타임스탬프 모드 기본 off.
- `LogViewerDock(QDockWidget)` — 위 위젯을 감싼다. 닫으면 삭제(WA_DeleteOnClose),
  MainWindow 가 `viewer_docks` 리스트로 관리(필터드뷰 `filter_views` 패턴).
- 대용량 경고: 선택 파일 합계가 200MB 를 넘으면 로드 전에 확인 모달(진행/취소).
- 정적 뷰이므로 tick/pump 대상이 아니다 — 소급 채움은 `reload()` 한 번.

### 3.3 MainWindow 연결

- 파일 메뉴에 "로그 파일 열기(뷰어)…" 추가 — `QFileDialog.getOpenFileNames`
  (Log (*.log *.txt);;All (*)) → `LogViewerDock` 생성, `Qt.BottomDockWidgetArea` 에 도킹.
- 여러 개 열면 Qt 가 자동으로 도크 탭으로 묶는다(추가 코드 없음). 드래그로 분리 가능.

## 4. 에러 처리

- 파일 열기 실패(권한·잠김·삭제) → 그 파일만 제외하고 상태줄 + 뷰어 상단에 사유 표시.
- 형식 판별 실패 → plain 으로 열화, 오류로 취급하지 않는다.
- 0바이트/빈 파일 → 소스는 등록하되 "0줄" 카운트로 표시.

## 5. 테스트 계획

- **selftest (core)**: 포트/병합/plain 3형식 파싱, TX·마커 복원, t_wall 복원,
  멀티 파일 시간순 병합과 seq 단조성, 소스 키 충돌 처리, 실패 파일 보고,
  pull_with_gap/last_seq 계약(ConsolePane 호환).
- **selftest --gui**: LogViewerWidget 에 파일 로드 → pane 내용·소스 체크박스·필터 동작,
  결과 저장, 닫을 때 정리(순환 참조 없음).
- **uitest**: 기록을 끝낸 실제 파일을 뷰어로 열어 검색·필터·저장, 병합+포트 파일 동시
  오픈 시 시간순, 도크 생성·닫기·분리(floating) 시나리오.
- i18n: 새 문구 전부 `tr()` + `i18n_en.py` (기존 selftest 가 자동 강제).

## 6. 범위 제외 (YAGNI)

- tail -f 식 실시간 추적 (라이브는 기존 콘솔이 담당)
- 뷰어 전용 하이라이트 편집 UI (프로파일 룰 재사용)
- 대용량 스트리밍/페이지네이션 (전체 로드로 확정)
